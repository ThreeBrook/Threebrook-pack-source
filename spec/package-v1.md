# IIS 包格式 v1（.iisz）

一个 `.iisz` 包把一个文件夹（含子文件夹）存成一个文件。用法像 ZIP。

格式就是标准 ZIP（PKWARE APPNOTE 6.3.x），只用其中最简单、最通用的部分，任何解压软件都能打开。图像的无损压缩不靠 ZIP，
而是把每张图像单独存为 IIS 容器（`spec/container-v1.md`），作为一个普通条目放进 ZIP。

实现：`src/core/src/package.cpp`。兼容性检查：`tools/pkg_zip_check.py` 用 Python 自带的 `zipfile` 读包。

## 1. 条目

| 条目 | 名称 | 数据 |
|---|---|---|
| 文件夹 | `顶层/子目录/`（以 `/` 结尾） | 无 |
| 压缩过的文件 | `顶层/子目录/原名.iis` | 该文件的 IIS 容器（容器 v1，已自检） |
| 原样存放的文件 | `顶层/子目录/原名` | 原文件字节 |

- 打包一个文件夹时，以文件夹名为唯一的顶层目录，所有条目都在它下面。
- 每个文件先按单文件规则压缩（`iis_compress`，含自检：独立读回、解码、重组、SHA-256 一致）。
  压缩后不比原文件小 1% 以上时原样存放。本身已是 IIS 容器的文件，以及 `.iisz` 文件，也原样存放。
- 包里有空文件夹时，也为它写一个条目，解出时还原。
- 条目按名称排序。符号链接与目录联接不跟随、不打包。

## 2. ZIP 的用法

- 所有条目只存不压：压缩方法 0，压缩前后长度相同。不加密、不分卷、没有数据描述符（通用标志第 3 位为 0）。
- 文件名一律 UTF-8，`/` 分隔，并置通用标志第 11 位。
- “生成版本”为 63，主机 0（MS-DOS）；外部属性：文件夹 `0x10`，文件 `0x20`。
- 本地头与中央目录头里的日期时间都是原文件修改时间（本地时间，2 秒精度）。
- CRC-32 按 ZIP 规范，对条目数据（容器或原文件字节）计算。
- 条目长度或本地头偏移达到 `0xFFFFFFFF`、条目数达到 `0xFFFF`、中央目录的长度或偏移达到 `0xFFFFFFFF` 时，使用 ZIP64：
  - 本地头：长度字段写 `0xFFFFFFFF`，并加 ZIP64 附加字段（`0x0001`），内含原长与压缩后长度；
  - 中央目录头：附加字段只含溢出的那几项，按原长、压缩后长度、本地头偏移的顺序；
  - 目录结尾：写 ZIP64 目录结尾记录与定位器，普通目录结尾里对应的字段写 `0xFFFF` / `0xFFFFFFFF`。

## 3. IIS 附加字段（`0x4949`，“II”）

每个文件条目在中央目录头里带一个附加字段，小端：

| 偏移 | 长度 | 内容 |
|---|---|---|
| 0 | 2 | 头标识 `0x4949` |
| 2 | 2 | 数据长度 50 |
| 4 | 1 | 版本 1 |
| 5 | 1 | 标志：第 0 位为 1 表示条目数据是 IIS 容器，解出时还原（名称去掉 `.iis`）；为 0 表示原样存放 |
| 6 | 8 | 原文件长度 |
| 14 | 32 | 原文件 SHA-256 |
| 46 | 8 | 原文件修改时间（FILETIME：1601-01-01 UTC 起的 100 纳秒数），0 表示未知 |

- 读取方遇到版本不是 1 的 IIS 附加字段，按没有附加字段处理。
- 没有 IIS 附加字段的条目一律原样解出，即使名称以 `.iis` 结尾。这样，别处来的普通 ZIP（只存不压）也能解；
  用户自己文件夹里本来就有的 `.iis` 文件，打包后也原样解出。

## 4. 写入

1. 先写临时文件 `包名.<8 位十六进制>.iistmp`，在目标包所在的文件夹里。
2. 写完后落盘（FlushFileBuffers / fsync）。
3. 读回整个文件，SHA-256 必须与写入的字节一致，并能按本规格读出全部条目。
4. 改名为最终的包；目标已存在时不覆盖（自动命名为 `名 (2).iisz`…）。
5. 要求删除原文件时，在上一步之后逐个独占打开原文件，长度与 SHA-256 都与打包时一致才删除，再由深到浅删除变空的文件夹。

任何一步失败或被取消，删除临时文件，原文件不受影响。

## 5. 读取与解出

1. 找目录结尾：从文件末尾向前找签名，要求注释长度与文件末尾吻合；有 ZIP64 定位器时读 ZIP64 目录结尾。
2. 拒绝：压缩方法不是 0、加密、压缩前后长度不同、条目越界的包。这样的包不是 IIS 生成的，请用普通解压软件打开。
3. 名称不安全的条目不解出，其余照常：
   - 名称为空，或某一段为空、`.`、`..`；
   - 含 `\ : * ? " < > |` 或控制字符（因此也不可能是盘符或绝对路径）；
   - 某一段以空格或 `.` 结尾。
4. 每个文件条目：
   - 核对 CRC-32；
   - 容器条目还原，并核对原文件 SHA-256：容器里记录的值与 IIS 附加字段里的值都要一致；
   - 原样条目有附加字段时，也核对 SHA-256；
   - 先写临时文件，落盘，再改名为目标文件；目标已存在时跳过、不覆盖；
   - 按附加字段设置修改时间。
5. “解压到此处”：
   - 包内只有一个顶层文件夹时，在包旁边还原这个文件夹；同名文件夹已存在时改名为 `名 (2)`…；
   - 否则在包旁边新建 `包名` 文件夹（同样避免重名），解到里面。

## 6. 不依赖 IIS 取回数据

- 任何解压软件都能列出并解出全部条目：
  - 原样存放的条目就是原文件；
  - `原名.iis` 条目可用开源解码器 `iis-decode`（`decoder/`，BSD-3-Clause）还原为原文件，并核对 SHA-256。
- 修改时间可从 ZIP 头的日期时间读到（2 秒精度），精确值在 IIS 附加字段里。
