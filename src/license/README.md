# 离线授权（T9）

设备离线运行，授权用“机器码 → 我方签发授权文件 → 设备导入”的方式完成。

## 流程

1. 设备上取机器码：管理界面“授权”页（可一键复制），或 `iis-service machine-code`。
   机器码只含指纹各项的哈希（`IIS1-…`），不含主板、硬盘序列号原文。
2. 我方用私钥签发（内部工具，不随产品发布）：

```bash
iis-license issue --key 生产私钥.key --machine IIS1-… --customer 客户 --device 设备编号 --days 365 --out 授权.lic
```

   也可 `--until 2027-12-31` 或 `--perpetual`，`--tier` 档位、`--feature` 功能项、`--from` 生效日。
   每次签发自动在私钥旁的 `签发记录.csv` 追加一行（编号、日期、客户、设备、档位、到期、机器码）。
3. 设备导入：管理界面“授权”页选择文件或粘贴（需管理员登录；只接受与本机相符、在有效期内的），或把文件放到
   配置文件旁的 `license.lic`（可用 `license_file` 改位置）。导入立即生效，记审计。

`iis-license verify 授权.lic [--machine 机器码]` 可在签发前后核对。

## 规则

| 项目 | 规则 |
|---|---|
| 签名 | Ed25519（RFC 8032，Monocypher 4.0.3），签名覆盖授权内容的规范化 JSON；改动任何字段即无效 |
| 公钥 | 编译进程序（CMake 选项 `IIS_LICENSE_PUBKEY`），不读外部公钥文件——换不掉 |
| 机器指纹 | 主板 UUID、主板序列号、CPU 型号与签名、系统盘序列号、物理网卡 MAC、Windows MachineGuid，各取哈希；取不到的项省略 |
| 换硬件容错 | 授权记录的各项中最多 1 项不一致（且至少 2 项一致）仍有效；更多时提示把新机器码发来重新签发 |
| 有效期 | 生效日、到期日（含当天）或永久；剩余 30 天内界面告警 |
| 系统时间回拨 | 记录观察到的最大时间（`data/clock.json`，并与审计日志最后一条的时间取较大者）；当前时间比它早 2 小时以上，或比签发时间早 1 天以上，判为“系统时间异常” |
| 不满足时 | 只是**不压缩新文件**；服务、管理界面、防爆盘、保留策略照常；已压缩文件的查看、还原、导出永远可用（查看器、iis-cli 的查看 / 校验 / 还原 / 导出、开源解码器都不检查授权） |
| `iis-cli compress` | 同样需要本机有效授权：`--license`，或程序旁的 `license.lic`，或 `%ProgramData%\IIS\license.lic` |
| 审计 | 导入记 `license`（编号、客户、设备、到期、备份），状态变化记 `license_state`（如 有效 → 已过期） |

## 密钥

- 生产密钥对由负责人生成并**离线保管**：`iis-license keygen --out 生产私钥.key`，把打印的公钥在构建时传给 CMake：
  `-DIIS_LICENSE_PUBKEY=<公钥>`。私钥丢失则无法再签发（已签发的仍有效），泄露则任何人都能签发——须换密钥并重新发布程序。
- 默认构建使用**开发用公钥**（私钥只在开发机 `.cache/license-dev/`，不入库）；这样的程序在日志、管理界面、`license` 命令里
  都会提示“开发用授权公钥”，不得用于正式发布。

## 测试

| 测试 | 内容 |
|---|---|
| `iis_license_tests` | RFC 8032 Ed25519 标准向量；签发 / 校验；改字段、换密钥、格式错误均无效；规范化后键顺序与空白不影响；机器码往返与容错；本机指纹稳定；有效 / 永久 / 到期边界 / 未生效 / 换 1 项仍有效 / 换 2 项不符 / 缺 1 项 / 时间回拨 / 签发时间在未来 |
| `iis_service_tests`（授权部分） | 引擎未授权不提交压缩、授权后立即压缩；服务无授权时照常运行并给出机器码；别的机器 / 被改过的授权拒绝导入、未登录不能导入；导入后立即压缩；到期后停止压缩但导出还原照常；时间回拨后停止压缩；审计记录 |
| `bench/tests/test_cli_tools.py` | iis-cli 无授权或授权无效时拒绝压缩并给出机器码；有授权时完整往返 |
