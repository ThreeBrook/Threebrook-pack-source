# iis-service：Windows 后台压缩服务

设备内嵌版（阶段 1）的 L0 无代码集成：监控视觉软件保存图像的目录，文件写完后在后台无损压缩为同目录的 `.iis`，
按配置释放原文件。压缩与原子提交由内核 `iis_compress_file` / 线程池完成（见 `src/core/README.md`），本服务负责
“什么时候、以多少资源去压哪个文件”（T5），索引、保留策略、防爆盘、导出、审计与统计（T6），以及本机管理界面（T7）。

## 运行

```bash
iis-service run --config config.json
```

控制台运行，Ctrl+C 停止（调试用）。运行后用浏览器打开 `http://127.0.0.1:8686/` 即本机管理界面（见下）。

```bash
iis-service check --config config.json
```

只检查配置。以下两条需要管理员权限：

```bash
iis-service install --config C:\ProgramData\IIS\config.json
```

```bash
iis-service uninstall
```

命令行工具（服务运行时也可使用，与服务共享索引与审计日志）：

```bash
iis-service export --config config.json --out E:\导出 --from 2026-11-01 --to 2026-11-02 --station cam1 --verdict NG --restore
```

按修改日期（含首尾两天）、工位、产品、批次（通配符）、OK/NG、监控目录筛选，导出到 `输出目录/<监控目录名>/<相对路径>`。
`--restore` 还原为原始格式（逐个比对 SHA-256 后才写出），否则复制 `.iis`；目标已存在不覆盖。每个文件与汇总都记审计。

```bash
iis-service audit-verify --config config.json
```

```bash
iis-service stats --config config.json
```

`audit-verify` 校验审计日志哈希链；`stats` 显示物理占用、等效容量、压缩比、OK / NG 数、最近每日吞吐。

```bash
iis-service set-password --config config.json
```

设置或重设管理界面的管理员密码（忘记密码时用；输入不回显），配置文件先备份，记审计；正在运行的服务立即按新密码校验。

`install` 注册服务：开机自启（延迟启动，不与视觉软件抢开机资源）；崩溃或异常退出后 5 秒、10 秒、之后每 60 秒自动重启，
一天无故障后计数清零；以非 0 退出码停止也算失败（如配置读不了）。`uninstall` 先停止服务再删除注册，**不删除任何图像与 `.iis`**。
`--name` 可改服务名（默认 `IIS`）。服务以 LocalSystem 运行，监控目录应在本机磁盘上：LocalSystem 看不到映射的网络驱动器。

正式部署使用安装包（`installer/README.md`），它会调用以下命令：

```bash
iis-service init-config --config C:\ProgramData\IIS\config.json --watch "D:\图像;E:\图像2" --port 8686 --license D:\授权.lic
```

配置文件不存在时生成它：`--from 预置配置.json` 原样采用，否则按 `--watch` / `--port` 生成，并**写全所有配置项的默认值**。
这样现场打开配置文件或管理界面就能看到每一项，需要时再改。默认值与解析代码同源（`defaults_json()`，取自 `Config{}`）。
配置已存在时**不做任何改动**（升级保留配置）。`--license` 只导入对本机有效的授权，旧授权先备份。参数有误时退出码非 0。

```bash
iis-service configure-service
```

给已登记的服务设置延迟启动与崩溃自动重启（与 `install` 相同）。

```bash
iis-service ui --config C:\ProgramData\IIS\config.json
```

等管理界面就绪（最多 30 秒）后用默认浏览器打开，供开始菜单快捷方式使用。`--no-browser` 只检查能否连上，用于测试。

## 配置（JSON，UTF-8，可带 BOM）

```json
{
  "watch": [
    {"path": "D:\\Images", "recursive": true, "include": ["*.bmp", "*.tif"], "exclude": ["calib/*"]}
  ],
  "raw_rules_file": "raw_rules.json",
  "delay_s": 3600,
  "threads": 2,
  "max_cores": 2,
  "pause": {"processes": ["Vision.exe"], "pause_percent": 60, "resume_percent": 40}
}
```

未知字段报错（拼错的字段不会被静默忽略）；相对路径按配置文件所在目录解析。

| 字段 | 默认 | 说明 |
|---|---|---|
| `watch[].path` | 必填 | 监控根目录（本地盘或网络共享）。`watch` 可以是空数组：服务照常运行但不压缩，管理界面提示添加目录（刚安装时） |
| `watch[].recursive` | true | 含子目录 |
| `watch[].include` | `*.bmp *.dib *.tif *.tiff *.raw` | 相对根目录、`/` 分隔的通配符（`*` 可跨目录，不区分大小写）。格式仍按内容识别；这里只决定“管哪些文件”，默认不碰视觉软件的日志、数据库、参数文件 |
| `watch[].exclude` | 空 | 排除的通配符 |
| `raw_rules_file` | 空 | RAW 参数规则（`iis_raw_rules_parse` 的 JSON）；同名参数文件 `a.json` 由内核自动读取 |
| `delay_s` | 3600 | 写完判定：最后修改后至少等待的秒数 |
| `stable_s` | 5 | 再确认大小与修改时间在这段时间内不变 |
| `retry_s` | 60 | 文件被占用、磁盘满等情况的重试间隔 |
| `rescan_s` | 3600 | 定期全量扫描补漏；0 = 只在启动、事件溢出、目录重建时扫描 |
| `release` | true | 提交后释放原文件；false 时只生成 `.iis`（试用 / 对比） |
| `min_saving` | 0 | 收益阈值 0~0.9 |
| `zstd_level` | 19 | 兜底 zstd 级别 |
| `threads` | 2 | 压缩线程数 |
| `max_cores` / `cores` | 不限 | 核亲和性：取编号最大的若干个逻辑核，或指定核编号 |
| `cpu_rate_percent` | 不限 | Job Object CPU 硬上限（占整机百分比） |
| `max_mb_s` | 不限 | 吞吐上限（按原文件字节） |
| `priority` | background | `background`：CPU、磁盘 IO、内存页都降到后台；`idle` / `below_normal` / `normal` |
| `min_free_mb` | 2048 | 所在盘剩余空间低于此值时暂停写 `.iis`，不与视觉软件抢最后的空间 |
| `pause.processes` | 空 | 检测进程名（不区分大小写） |
| `pause.pause_percent` / `resume_percent` | 60 / 40 | 这些进程合计 CPU（占整机百分比）达到前者时暂停，低于后者持续 `resume_after_s`（10 秒）后恢复；采样间隔 `sample_s`（1 秒） |
| `watch[].quota_mb` | 不限 | 本目录受管文件合计占用上限：防爆盘把“配额剩余”与“盘剩余”取较小者作为剩余空间 |
| `data_dir` | `data` | 索引 `index.db`（SQLite）与审计日志 `audit/audit-YYYYMM.log` |
| `classify.templates` | 空 | 路径模板识别工位 / 产品 / 批次 / OK-NG，如 `{station}/{batch}/{verdict}/*`（见下） |
| `classify.ng_globs` / `ok_globs` | 空 | 模板未给出 OK/NG 时按通配符判定 |
| `classify.ng_words` / `ok_words` | NG NOK FAIL BAD REJECT / OK PASS GOOD | 再按路径中的整词判定（`word_rule`，默认开） |
| `classify.unknown_as` | `ng` | 识别不出 OK/NG 的文件：`ng` 当作 NG 保护（不被防爆盘删除）；`ok` 当作 OK |
| `retention` | 空 | 保留规则数组 `{"station","product","verdict","days"}`，按顺序取第一条匹配；`days` 为 0 永久保留；`verdict` 为 `*` 时不含 NG——NG 只能由写明 `"NG"` 的规则删除 |
| `retention_interval_s` | 600 | 保留规则检查间隔 |
| `disk.warn_free_percent` / `warn_free_mb` | 15% / 0 | 剩余低于此值：告警 + 加速压缩（`accelerate_threads` 个线程，默认 2 × threads；写完判定延迟缩短到 `accelerate_delay_s`，默认 300 秒） |
| `disk.delete_free_percent` / `delete_free_mb` | 8% / 0 | 剩余低于此值：按修改时间从旧到新删除可删除的 OK 图 |
| `disk.target_free_percent` / `target_free_mb` | 10% / 0 | 删到剩余回到此值为止 |
| `disk.check_s` | 10 | 空间检查间隔 |
| `ui.enabled` / `ui.port` | true / 8686 | 本机管理界面；只监听 127.0.0.1，端口修改要重启服务 |
| `ui.password` | 无 | 管理员密码的盐与哈希（PBKDF2-HMAC-SHA256，10 万次）；由界面或 `set-password` 写入，不要手改 |
| `license_file` | `license.lic` | 授权文件（相对路径按配置文件所在目录） |
| `log_dir` | `logs` | 日志目录：`iis-service-YYYYMMDD.log`，保留 `log_keep_days`（30）天 |
| `status_file` | `log_dir/status.json` | 状态文件，每 `status_s`（60）秒更新：计数、字节、等待 / 就绪 / 处理中、暂停、空间不足、在线目录数 |

## 工作方式

1. **启动恢复**：先对每个监控根目录运行 `iis_recover_dir`（清理残留临时文件、释放已有一致 `.iis` 的原文件），再开始压缩。
2. **发现文件**：每个根目录一个 `ReadDirectoryChangesW` 监控线程（64 KB 缓冲区，网络共享的上限）。启动时、事件缓冲区溢出时、
   监控目录被删除重建时、以及每 `rescan_s` 秒做一次全量扫描补漏。新建或移入的子目录会单独扫描。
3. **写完判定**（三道关，全部满足才压缩）：
   - 最后修改时间已过 `delay_s`（用单调时钟计时；系统时间回拨、修改时间在“未来”时最多等 `delay_s`，不会卡住）；
   - `stable_s` 内大小与修改时间不变；
   - 独占打开测试：以拒绝他人写入的方式打开后立即关闭；别人正以写方式打开着就失败，`retry_s` 后再试。
     这只发生在文件已静止 `delay_s` 之后，打开时间是微秒级，不会锁住正在写的文件。
4. **提交**：交给内核线程池（读原文件不妨碍他人；临时文件 → 落盘 → 读回 → 改名 → 独占复核后释放）。线程池队列保持很短
   （线程数 + 1），暂停能及时生效。
5. **结果处理**：原文件被占用暂未释放 → 稍后再释放；原文件在压缩后被修改 → 重新计时；压不小 / 冲突 / 连续失败 3 次 → 记住
   （大小与修改时间不变就不再处理，文件变化后重新处理）；保留原文件模式下已有更新的 `.iis` 不重复处理。
6. **资源控制**：后台优先级、核亲和性、Job Object CPU 上限、吞吐上限、检测进程 CPU 高时暂停、剩余空间保护。
7. **停止**：不再取新文件，等正在压缩的文件做完（通常 1 秒内）；排队中的文件原文件都还在，下次启动重新发现。

服务异常（崩溃、被杀、卡住）时，视觉软件写图不受影响：服务从不长时间打开图像文件，最坏情况只是不压缩。

## 离线授权（T9）

服务启动时取本机指纹，按配置文件旁的 `license.lic`（`license_file` 可改）判定授权，之后每分钟复核一次。
**未授权、过期、与本机不符、系统时间异常时只是不压缩新文件**；服务、管理界面、存储管理照常运行，已压缩文件的查看、还原、导出永远可用。
管理界面“授权”页显示状态与机器码并可导入授权；也可用 `iis-service machine-code`、`iis-service license --config 配置.json`。
规则与签发流程见 `src/license/README.md`。

## 存储管理（T6）

**索引**（`data_dir/index.db`，SQLite WAL）：每个受管文件一行，键为原文件路径——路径、工位、产品、批次、OK/NG、原文件修改时间、
原始大小、占用大小、原文件 SHA-256、状态（待压缩 / 已压缩 / 原样保存 / 已删除）。索引只是加速与统计，真实状态以磁盘为准：
删掉索引后重启，扫描到的 `.iis` 会按容器头（原始大小、SHA-256）重新登记；被外部删除的文件标为已删除并记审计 `missing`。

**识别**：路径模板 `{station}` `{product}` `{batch}` `{verdict}` 各匹配一个路径段内的文字，`*` 段内任意、`**` 跨目录，
不区分大小写，取第一个匹配的模板；没给出 OK/NG 时依次用 `ng_globs` / `ok_globs`、路径中的整词；同时出现 NG 与 OK 词按 NG。
工位默认取第一级目录名。

**防爆盘**（每 `disk.check_s` 秒）：剩余 = 盘剩余（设了配额时再与“配额 − 已占用”取较小者）。
低于告警阈值 → 告警、加速压缩（压缩本身就能腾出空间）；低于删除阈值 → 按修改时间从旧到新删除可删除的图（OK；
`unknown_as=ok` 时含未知），删到目标值。**NG 永远不会被防爆盘删除**；没有可删的图时只记错误并在状态里标 `stuck`。
正在压缩的文件跳过（删除与提交互斥）。另有 T5 的 `min_free_mb`：剩余低于它时不再写 `.iis`。

**保留策略**（每 `retention_interval_s` 秒）：按第一条匹配的规则删除超过保留天数的文件（按原文件修改时间）。

**审计日志**（`data_dir/audit/audit-YYYYMM.log`）：每行一条 JSON（动作、路径、详情、序号、时间、上一条哈希、本条哈希），
记录压缩（含方式、大小、SHA-256、原文件是否释放）、释放、删除（原因、OK/NG、释放字节）、导出、外部删除、恢复、配置变更
（配置文件 SHA-256 变化）、启动、停止。改动、删除、插入、调换任何一条，`audit-verify` 都会指出位置；
断电留下的半行在下次追加时截掉并记 `audit_repair`。只追加、多进程安全（文件锁）。

**统计**：`status.json` 增加每个监控目录的物理占用、等效容量（只作统计，不作为可用容量报告）、压缩比、容量、剩余、
告警级别与阈值，OK / NG / 未知数，最近 14 天每日压缩与删除，审计最后序号与哈希；`stats` 命令同样可查。

## 本机管理界面（T7）

服务内置一个只监听 `127.0.0.1` 的网页（中文），浏览器打开 `http://127.0.0.1:8686/`：

| 页面 | 内容 |
|---|---|
| 总览 | 运行状态与告警（引擎未运行、目录不可用、空间告警 / 删除中 / 无图可删、因检测软件忙暂停、NG 被删除）、本次运行计数、每个监控目录的剩余 / 容量 / 物理占用 / 等效容量 / 压缩比 / 阈值、OK/NG 数、最近每日吞吐图表；每 3 秒刷新 |
| 监控目录 / RAW 参数 / 识别与保留 / 防爆盘 / 压缩与资源 | 配置的全部字段（表单），每一项都预先填好默认值（配置文件里没写的项按服务提供的默认值显示，保存时一并写入），默认选项标“（默认）”；RAW 规则表直接写规则文件 |
| 高级（配置文件） | 直接编辑整个 JSON |
| 导出 | 按日期、工位、产品、批次、OK/NG、目录导出（还原或保持压缩），显示进度；导出目录不能在监控目录里 |
| 日志 / 审计 | 按天的日志（级别过滤、搜索）；审计记录（按动作过滤、搜索）与一键完整性校验 |
| 管理员密码 | 设置 / 修改密码 |
| 授权 | 授权状态（T9 实现） |

**改配置要二次确认**：表单修改后点“保存修改…”→ 服务端校验并给出与当前文件的逐行差异、改动项与提醒（如目录不存在、
将开始 / 停止释放原文件、需重启才生效的项）→ 点“确认应用”才写入。写入前备份原文件（`config.json.bak-时间`，保留最近 20 个），
原子替换后重载压缩引擎（正在压缩的文件先做完），并在审计日志记一条 `config`（改动项、来源、备份文件、新旧 SHA-256）。
校验不通过时给出带字段位置的中文错误，不保存。

**选择文件夹**：“添加监控目录…”与每个目录的“选择文件夹…”打开文件夹浏览框（须登录）。
服务在后台运行、弹不出系统的选择框，所以由服务端列出盘符与子文件夹（`POST /api/browse`，只读，不含文件和隐藏的系统文件夹，最多 5000 个）。
列出的是服务账户（LocalSystem）能访问的文件夹，正是它能监控的。网络共享可在路径框直接输入 `\\服务器\共享`。
新加的目录只需选路径，其余各项（含子目录、处理的文件类型、配额）按默认值填好。

**配置坏了也能用界面修**：配置文件无法解析时引擎不启动，但界面照常（端口取默认 8686），可在“高级”里改好，确认后自动启动。

**管理员密码**：查看状态、日志、审计不需要登录；修改配置、导出、改密码需要登录。还没设密码时，第一次要改东西会先让设密码。
密码只以 PBKDF2-HMAC-SHA256（随机盐、10 万次）哈希存在配置里；连续 5 次输错锁定 60 秒；登录 30 分钟不操作自动失效；
改密码后其他会话失效；密码不能经“改配置”修改或删除（提交的配置没写密码时沿用现有的）。忘记密码在本机用 `set-password` 重设。
设置与修改都记审计（不含密码）。例外：配置文件坏了且不知道密码时，允许不登录修配置（能弄坏配置文件的人本来就能直接改它）。

**安全**：只监听 127.0.0.1；请求的 Host 必须是本机地址（防 DNS 重绑定），带了来源（Origin）的必须是本页；
改动类请求必须带本进程的会话码（别的网页读不到）且为 JSON；响应禁止被嵌入框架、禁止缓存。

| 测试 | 内容 |
